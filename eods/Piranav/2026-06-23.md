Diagnostic Reflection
What was tried
Investigated PageSpeed Insights accessibility failures.
Audited all homepage banner implementations.
Tested Liquid fallback behaviour for whitespace values.
Investigated Lighthouse SEO requirements for descriptive links.
Performed complete predictive search architecture review.
Designed two independent search enhancement solutions.
What worked
strip before default successfully protects against whitespace-only values.
Visually hidden descriptive text satisfies Lighthouse while preserving UI.
Existing predictive search architecture allows extension without replacing Shopify native search.
Global search controller enables standalone enhancement with minimal risk.
What failed and why
Remaining accessibility issues in:
banner-image.liquid
banner-with-text.liquid
These were intentionally deferred to maintain scope and prioritise the PageSpeed blocker.
Where time was wasted
Deep investigation into Shopify Predictive Search limitations before confirming API constraints around metafields and intent matching.
Additional architecture analysis required to identify non-invasive integration points.
What will change tomorrow
Resolve remaining banner accessibility issues.
Begin implementation of Phase 1 predictive search improvements.
Continue development of the standalone AI Lighting Advisor.
Lessons Learned / Actionable Next Steps
Always sanitize merchant-entered text before using Liquid fallback chains.
Lighthouse requires descriptive anchor content, not only aria-label.
Native Shopify Predictive Search benefits significantly from better field selection and tag taxonomy before considering third-party search platforms.
Standalone architecture reduces deployment risk and simplifies maintenance.
Questions for STL / Team Leader / LLM
Should remaining accessibility fixes be bundled into one deployment or released independently?
Should Phase 1 search improvements be prioritised before AI Lighting Advisor implementation?
Is product tag taxonomy available for expanding search intent coverage?

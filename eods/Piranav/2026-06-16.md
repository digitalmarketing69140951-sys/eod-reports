What worked

What failed and why
Breadcrumb issue could not be fully resolved because the underlying collection context is not currently passed from product listing cards.
Active navigation substring matching issue was identified but intentionally deferred to avoid scope expansion.
Where time was wasted
Investigating multiple interconnected Liquid snippets before identifying that collection context was lost at the product card level.
Verifying shared CSS variables across multiple components to ensure global accessibility changes would not introduce regressions.
What will change tomorrow
Implement the breadcrumb collection context fix using product.url | within: collection.
Replace hardcoded collection index fallback with deterministic collection selection logic.
Continue Lighthouse optimisation for remaining accessibility and SEO opportunities.
Lessons learned / Actionable Next Steps
Avoid relying on product.collections[index] because Shopify collection ordering is not deterministic.
Always preserve collection context when generating product URLs.
Prefer reusable CSS classes over inline styling for maintainability and accessibility.
Apply defensive guards when referencing optional global JavaScript objects.
Validate browser resource loading against actual @font-face URLs before introducing preload hints.
